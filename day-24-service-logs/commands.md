- systemctl list-units --type=service: This command generates a complete master list of all active background service units currently loaded into your system's memory, displaying their immediate runtime status and descriptions.
- systemctl list-units --state=failed: This one serves as a troubleshooting filter. It skips healthy services and prints a clean leaderboard of only the background applications that have crashed, broken down, or failed to start, allowing you to spot system issues instantly.
- systemctl daemon-reload: It instructs the system manager to completely refresh its internal checklist. If you manually modify a configuration script or create a brand-new .service unit file, you must run this command so the system recognizes the changes before you can start or enable the service.
- journalctl: By default, running just journalctl opens a massive, scrollable ledger of every system log message recorded since the machine was installed. To make sense of it, we use specific filters like the ones below.
- journalctl -f: This command follows the system log streams in real-time. The terminal stays open and automatically scrolls new event notifications, errors, and system warnings across your screen as they happen. Pressing Ctrl + C will stop following.
- journalctl -u: It filters the log ledger to isolate only the messages belonging to a specific service (e.g., journalctl -u ssh). This cuts out the background noise of other applications when you are trying to diagnose a broken app.
- journalctl --since: Restricts the search to a specific historical window so you don't waste time scrolling through old records (e.g., journalctl --since "1 hour ago" or journalctl --since "2026-09-02 18:00:00").
- journalctl -p err: Filters messages strictly by their priority (-p) tier. It hides mundane informational alerts and prints only entries flagged as Error or higher (including critical crashes and emergencies).
## While journalctl manages modern binary logs, many systems and services still write standard plain-text records to the historical /var/log directory.
- tail -f /var/log/syslog: It streams the global system log text file in real-time. It catches a wide array of non-kernel deployment messages, script breakdowns, and general application alerts. (On Red Hat/CentOS systems, this file is named /var/log/messages).
- tail -f /var/log/auth.log: This also streams the system security and authentication logs in real-time. It tracks every user login session, privilege escalation request via sudo, and failed SSH connection attempts (making it your first stop when investigating a potential brute-force security breach). (On Red Hat systems, this is found at /var/log/secure).
