- function_name() { }: Groups a block of reusable code together. Functions keep scripts clean, readable, and dry by allowing you to define a task once and call it multiple times by its name later.
- $1/$2 positional args: These are variables that hold input data passed straight into a script or function when it is executed. For example, if you run ./script.sh cloud monkey, then $1 holds cloud and $2 holds monkey.
- $#/$*/$@: ($#) Displays the total count of arguments passed to the script, ($*) Bundles all arguments into a single, combined text string ("$1 $2 $3") and ($@) explodes all arguments into individual, separate strings ("$1" "$2" "$3"). This is the preferred method for passing arguments safely into loops.
- $0: This one holds the literal name of the script or execution path currently being run (e.g., ./backup.sh).
- exit codes ($?): Every Linux command outputs a hidden numeric status code from 0 to 255 when it finishes. Evaluating $? immediately tells you how it went. A 0 means total success, while any number greater than 0 points to a specific error or failure.
- crontab syntax: Cron reads a five-position time configuration layout to schedule recurrent tasks automatically. Cron syntaxing is using the he five field time format (minute, hour, day, month, weekday) used to schedule cron jobs
- cron scheduling (0 * * * *): Cron reads a five-position time configuration layout to schedule recurrent tasks automatically. A cron expression meaning run at the top of every hour. (0 * * * *) executes the task exactly at minute 0 of every single hour (hourly) while (30 2 * * *)  executes the task every single night at 2:30 AM and (0 0 * * 1) executes the task every Monday at midnight.
- nohup script.sh &: This command wraps the script so it ignores hangup signals (SIGHUP). The & pushes it into the background. This ensures long-running scripts run to completion even if your SSH connection completely drops out.
- trap: Intercepts structural OS signals (like an interrupt Ctrl+C or a script termination) before they kill your application. It lets you run an emergency cleanup function to delete temporary files or close connections before the script safely dies.
- logger: This is a vital utility that sends a custom text line directly into the centralized system log files (/var/log/syslog or systemd journal). This allows your automation scripts to record their errors and updates right alongside core operating system logs.
